# 제품 요구사항

## 1. 범위

제품은 개발자가 회사의 서비스 기획서를 입력하고 외부 근거 조사와 내부 일관성 검증을 거쳐 통합 평가 리포트를 받는 기능부터, 평가 결과 기반 자동 보완, 신규 자율 기획, 화면·UX 설계와 실행 가능한 React UI 생성까지 제공한다.

우선순위는 `필수`, `권장`, `후속`으로 구분한다.

### 3.1 인증 요구사항

| ID | 요구사항 | 우선순위 | 인수 조건 |
|---|---|---|---|
| AUTH-001 | Google OAuth로 로그인해야 한다 | 필수 | OAuth 클라이언트의 내부·외부 사용자 설정에 따라 로그인 후 JWT가 발급됨 |
| AUTH-002 | 보호된 웹 페이지에 navigation guard를 적용해야 한다 | 필수 | 유효한 인증이 없으면 보호 페이지를 표시하지 않음 |
| AUTH-003 | API 요청에 `Authorization: Bearer <JWT>` 헤더를 사용해야 한다 | 필수 | 헤더가 없거나 유효하지 않으면 API가 401을 반환함 |
| AUTH-004 | 프론트엔드와 API 인증 상태가 모두 유효해야 한다 | 필수 | 어느 한쪽이라도 실패하면 세션 만료 다이얼로그가 표시됨 |
| AUTH-005 | 세션 만료 다이얼로그 확인 후 로그인 페이지로 이동해야 한다 | 필수 | 확인 시 인증 상태를 정리하고 로그인 라우트로 이동함 |
| AUTH-006 | 인증 실패를 중복 알림하지 않아야 한다 | 필수 | 동시 401 응답에도 다이얼로그가 한 번만 표시됨 |
| AUTH-007 | OAuth와 JWT 설정을 환경변수로 주입해야 한다 | 필수 | 코드와 저장소에 비밀값이 포함되지 않음 |
| AUTH-008 | JWT를 브라우저 `localStorage`에 저장해야 한다 | 필수 | 로그인 성공 후 저장되고 로그아웃·인증 실패 시 제거됨 |
| AUTH-009 | 모든 JWT에 `exp` 클레임이 있어야 한다 | 필수 | `exp`가 없거나 만료된 토큰은 프론트엔드와 API 모두 거부함 |
| AUTH-010 | 토큰 만료를 보호 화면 진입 및 API 호출 전에 확인해야 한다 | 필수 | 만료 확인 즉시 세션 만료 흐름이 실행됨 |

## 4. 외부 연동

- LLM 공급자: Intelligence 서비스를 통해 Claude, Grok, OpenAI 중 환경변수로 선택
- AI 웹 검색 공급자: Intelligence 서비스를 통한 Gemini API의 Google Search Grounding
- 문서 저장소: 로컬 실행과 향후 확장이 가능한 저장 방식
- 관계형 데이터베이스: 구현 단계의 아키텍처 규칙에 따라 선택
- 공공데이터 API: 조사 과제에 따라 동적 연결
- 작업 큐: Redis
- 인증: Google OAuth + JWT
- 실행 방식: 로컬 실행 우선

### 4.1 환경변수 누락 정책

| 설정 | 누락 시 동작 |
|---|---|
| Intelligence 서비스의 선택된 LLM API 키 | 해당 LLM 작업 시작 차단 및 설정 오류 |
| Intelligence 서비스의 Gemini API 키 또는 Grounding 모델 | 웹 조사를 건너뛰고 제한된 평가 수행 |
| Intelligence 서비스 연결 | LLM·AI 검색 작업을 차단하되 가능한 내부 규칙 검사는 유지 |
| OAuth·JWT 필수 설정 | 인증 서비스 시작 차단 |
| PostgreSQL 연결 | 상태 저장 서비스 시작 차단 |
| Redis 연결 | 비동기 평가 시작 차단, 조회 기능은 유지 |
| 선택 커넥터 키 | 해당 커넥터만 비활성화 |
| 문서 암호화 키 | 암호화 기능 비활성 상태를 명확히 표시 |

실행 중 키를 입력받는 화면은 제공하지 않는다. 설정 변경은 환경변수 갱신과 서비스 재시작으로 적용한다. 구체적인 환경 파일의 이름, 위치와 형식은 제품 문서에서 별도로 고정하지 않고 저장소의 `AGENTS.md`, `yj-arch-core` 및 해당 서비스의 플랫폼 스킬을 따른다.

## 5. 완료 기준

실제 회사 기획서의 핵심 문제를 탐지하고 근거를 확인할 수 있어야 한다. 수정본 재평가, 자동 보완, 신규 자율 기획, 화면·UX 설계, 실행 가능한 React UI 생성과 기존 구현 검증까지 하나의 추적 가능한 흐름으로 동작해야 한다.
