# 통합 평가 리포트 명세

## 1. 목적

통합 평가 리포트는 작성자, 개발자, 검토자와 승인권자가 같은 사실과 판정을 확인하고 실행 여부를 결정하기 위한 단일 결과물이다.

## 2. 출력 원칙

- 결론을 먼저 제시한다.
- 작성자에 따라 표현이나 심각도를 조정하지 않는다.
- 모든 문제는 원문 위치와 근거로 연결한다.
- 사실, 외부 근거, 추론과 미확인 사항을 구분한다.
- 리포트는 결함, 위험, 미검증 사항과 필요한 조치에 집중한다.
- 리포트 자체가 원문 전체를 다시 읽지 않아도 판단 가능한 수준이어야 한다.

## 3. 리포트 구조

### 3.1 헤더

- 프로젝트명
- 평가 대상 문서와 버전
- 평가 일시
- 적용 국가·도메인·사용자
- 평가 기준 및 모델 버전
- 조사 범위와 제한

### 3.2 요약 판정

- 종합 판정
- 판정 신뢰도
- 한 문장 결론
- 차단·높음·보통·낮음 문제 수
- 구현 시작 가능 여부
- 다음 필수 행동

### 3.3 기획 재구성

- 해결하려는 문제
- 기획 목적과 목표
- 대상 사용자와 환경
- 제안한 해결책
- 핵심 전제와 의존성
- 성공 기준

문서에 없는 내용은 보완해서 쓰지 않고 `정의되지 않음`으로 표시한다.

### 3.4 핵심 문제

종합 판정을 결정한 문제를 심각도순으로 표시한다. 각 항목은 문제 ID, 원문 위치, 판정, 근거, 영향과 필수 보완 조건을 포함한다.

### 3.5 영역별 평가

평가 영역마다 `충족`, `부분 충족`, `미충족`, `미검증`, `해당 없음`, `건너뜀` 상태와 주요 근거, 문제 수 및 판정 신뢰도를 제공한다. 총점은 제공하지 않는다. 적용하지 않은 영역에는 그 이유를 표시한다.

### 3.6 전체 문제 목록

필터와 정렬 기준:

- 심각도
- 평가 영역
- 문제 유형
- 문서
- 해결 상태
- 신뢰도

### 3.7 전제 및 의존성

- 확인된 전제
- 거짓으로 확인된 전제
- 미확인 전제
- 필요한 데이터·API·기술·권한·비용
- 확보 가능 여부와 확인 근거
- 데이터별 존재·접근·비용·상업적 이용 판정
- 라이선스·약관 원문과 저장·가공·AI 처리·파생 결과 제공·재배포 제한

### 3.8 내부 상충

충돌하는 두 개 이상의 원문 위치를 나란히 제시하고, 동시에 성립할 수 없는 이유와 필요한 결정을 설명한다.

### 3.9 조사 결과

- 조사 질문
- 확인 결과
- 사용한 원출처
- 반대 또는 상충 근거
- 적용 범위
- 확인 시점
- 남은 불확실성
- 수치의 원문 값·위치·단위·기간·표본과 기획서 값의 차이

### 3.10 보완 및 최종 권고

- 실행 전 필수 보완
- 후속 개선
- 작성자 또는 결정권자가 답할 질문
- 승인·조건부 승인·반려·재작성·중단 권고
- 판정을 변경하기 위한 조건

### 3.11 평가 한계

- 접근할 수 없었던 자료
- 검증하지 못한 전제
- 오래되었거나 신뢰도가 낮은 자료
- 모델 판단에 의존한 부분
- 키 또는 연동 설정이 없어 건너뛴 조사
- 해당 기획에 적용하지 않은 검증 영역과 이유

## 4. 문제 표시 예시

```text
[DAT-003] 필요한 사용자 단위 이동 데이터의 확보 가능성이 확인되지 않음

심각도: 차단
신뢰도: 높음
원문: 요구사항 3.2 “공공데이터를 이용해 개인별 이동 경로를 분석한다.”
판정: 확인된 공공데이터는 집계 통계이며 개인별 이동 경로를 제공하지 않는다.
영향: 핵심 추천 기능의 입력 데이터를 구성할 수 없다.
근거: 데이터 제공기관 공식 명세, 필드 목록, 이용 조건
보완 조건: 대체 데이터 공급자와 계약 가능성을 확인하거나 기능을 집계 데이터 기반으로 재설계한다.
검증 방법: 실제 샘플 데이터와 이용 권한을 확보해 필수 필드를 확인한다.
```

## 5. 재평가 표시

수정본에서는 각 문제를 다음 상태로 표시한다.

- 해결됨
- 부분 해결
- 미해결
- 악화됨
- 신규 발견
- 근거 변경으로 철회됨

종합 판정이 변경되면 변경 원인을 함께 표시한다.
