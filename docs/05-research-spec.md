# 조사 및 근거 명세

## 1. 목적

이 문서는 기획의 외부 사실과 핵심 전제를 검증하기 위한 조사 방법, 출처 기준과 증거 보존 방식을 정의한다.

## 2. 조사 원칙

- 빠른 답변보다 정확성과 재검증 가능성을 우선한다.
- 검색 결과나 LLM 기억보다 원출처를 우선한다.
- 대상 도메인, 국가, 기간과 사용자 조건을 일치시킨다.
- 사실과 해석을 분리한다.
- 핵심 판정은 가능한 경우 독립된 출처로 교차검증한다.
- 찾지 못한 사실을 존재하지 않는다고 즉시 단정하지 않는다.

## 3. 출처 등급

| 등급 | 출처 | 사용 원칙 |
|---|---|---|
| A | 원천 데이터, 법령, 정부·표준기관, 공식 API 문서 | 핵심 판정의 우선 근거 |
| B | 원문 논문, 공급자 공식 자료, 감사 가능한 기업 공시 | 조건과 이해관계를 확인 후 사용 |
| C | 신뢰할 수 있는 산업 보고서와 전문기관 분석 | 원출처가 없을 때 보조 근거 |
| D | 언론, 블로그, 커뮤니티, 사용자 사례 | 탐색과 보조 정황에만 사용 |
| E | LLM 추론 | 검증 질문 생성에 사용하며 외부 사실의 단독 근거로 금지 |

## 4. 조사 계획

각 기획에서 다음 절차로 조사 작업을 생성한다.

1. 종합 판정에 영향을 주는 핵심 전제를 추출한다.
2. 전제별로 참·거짓을 구분할 검증 질문을 만든다.
3. 필요한 데이터와 적합한 출처 유형을 정한다.
4. 국가·도메인·기간 조건이 포함된 검색 전략을 만든다.
5. 차단 가능성이 높은 질문부터 조사한다.
6. 상충 근거를 함께 탐색한다.
7. 결과와 한계를 기록한다.

조사 항목과 깊이는 프로젝트마다 달라진다. 데이터 의존성이 없는 기획에는 데이터 확보 검증을 강제하지 않으며, API를 사용하지 않는 기획에는 API 검증을 실행하지 않는다. 반대로 핵심 전제가 특정 국가의 법률, 시장 규모 또는 실시간 데이터에 의존하면 해당 검증을 우선하고 더 깊게 수행한다.

## 5. 설정 누락과 폴백

| 누락 설정 | 처리 |
|---|---|
| Intelligence 서비스의 선택된 LLM 공급자 키 | 관련 분석·조사·평가 작업을 시작하지 않고 설정 오류 표시 |
| Intelligence 서비스의 Gemini API 키 또는 Google Search Grounding 모델 설정 | 웹 검색을 건너뛰고 내부 문서 평가 진행, 외부 전제는 `미검증` 처리 |
| Intelligence 서비스 연결 | LLM·AI 검색이 필요한 작업을 중단하고 가능한 내부 규칙 검사만 유지 |
| 선택 커넥터 키 | 해당 커넥터만 비활성화하고 나머지 평가 진행 |
| 외부 데이터 API 키 | 공개 자료로 대체 조사, 불가능하면 해당 전제를 `미검증` 처리 |

키 누락을 외부 사실이 충족된 것으로 해석하지 않는다. 핵심 전제를 확인하지 못하면 `제한된 조사`를 표시하고 실행 가능 판정을 금지한다.

## 6. 대상별 검증

### 6.1 통계와 공공데이터

- 제공기관과 원본 데이터셋
- 조사 대상, 지역, 기간과 표본
- 필드, 단위와 집계 수준
- 갱신 주기와 최신 데이터 시점
- 결측·편향·정확도
- 실제 다운로드·API 접근 가능 여부와 필요한 가입·심사·계약
- 무료·부분 무료·유료·가격 협의 구분과 예상 사용량 기준 비용
- 라이선스 원문, 이용약관과 상업적 이용 가능 여부
- 원본 저장·가공·AI 처리·파생 결과 제공·재배포 허용 범위
- 출처 표시, 동일조건변경허락, 지역·업종·사용량 등 준수 조건
- 기획에 필요한 수준과의 차이

데이터의 존재만으로 확보 또는 사용 가능 판정을 내리지 않는다. 다음 상태를 각각 기록한다.

| 판정 축 | 상태 |
|---|---|
| 존재 | 확인됨·확인되지 않음·존재하지 않음 |
| 접근 | 즉시 가능·조건부 가능·계약 필요·접근 불가·확인 불가 |
| 비용 | 무료·부분 무료·유료·가격 협의·확인 불가 |
| 상업적 이용 | 가능·조건부 가능·별도 계약 필요·불가·확인 불가 |

라이선스 또는 약관이 없거나 해석이 불명확하면 무료라는 이유로 상업적 이용 가능으로 판정하지 않고 `확인 불가`로 남긴다.

### 6.2 API

- 실제 서비스 및 공식 문서 존재
- 필요한 기능과 응답 필드
- 인증과 접근 승인 가능성
- 호출량, 지연시간과 가용성 제한
- 가격과 예상 사용 비용
- 이용약관, 데이터 저장과 재배포 제한
- 지역 제한, 폐지 공지와 버전 정책
- 대체 API 및 자체 구현 가능성

### 6.3 논문

- 원문과 출판 상태
- 연구 대상과 표본 규모
- 실험 조건과 비교 기준
- 결과의 효과 크기와 한계
- 재현성 및 후속 연구
- 현재 기획의 국가·도메인·사용자와 차이
- 제품 환경에서 필요한 데이터와 비용

### 6.4 수치와 정량 주장

1. 기획서에서 수치와 연결된 주장 및 인용 출처를 추출한다.
2. 수치의 대상, 정의, 단위, 지역, 기간, 표본과 계산 기준을 식별한다.
3. 검색 결과나 뉴스의 재인용에 머물지 않고 원문 통계표, 데이터셋, 논문 또는 기업 공시로 이동한다.
4. 원출처에서 실제 값, 표·페이지·항목 위치와 가공 또는 계산 과정을 확인한다.
5. 가능하면 독립된 출처로 값과 적용 범위를 교차검증한다.
6. 기획서 수치와의 차이, 차이 원인과 판정 영향을 기록한다.

뉴스와 2차 보고서는 원출처 탐색 및 보조 정황으로 사용할 수 있지만 핵심 수치의 단독 확정 근거로 사용하지 않는다. 원문을 찾지 못하면 해당 수치를 `미검증`으로 처리한다.

### 6.5 벤치마킹

- 같은 문제와 사용자를 대상으로 하는지
- 실제 제공 기능과 마케팅 표현의 차이
- 대상 국가, 가격, 규모와 운영 조건
- 서비스 지속 여부와 확인 시점
- 성공을 주장할 수 있는 객관적 자료
- 그대로 적용할 수 없는 차이

### 6.6 기술

- 공식 기술 문서와 구현 사례
- 요구 성능과 정확도 달성 여부
- 필요한 데이터와 인프라
- 구축·운영 비용과 전문 인력
- 보안·개인정보·라이선스 제약
- 실패 조건과 대체 설계

## 7. 교차검증

웹 탐색은 Gemini의 Google Search Grounding을 사용하되, 모델이 합성한 답변이나 검색 스니펫을 원출처로 취급하지 않는다. Grounding 응답에서 실제 실행 질의, 출처 URL과 인용 연결을 수집하고, 조사 기능이 해당 URL을 직접 방문해 본문·최종 URL·확인 시점·콘텐츠 해시를 보존한다. 이후 공식성, 적용 범위, 최신성과 주장 일치 여부를 별도로 판정한다.

다음 항목은 가능한 한 두 개 이상의 독립된 근거로 확인한다.

- 시장 규모와 사용자 수
- 핵심 문제의 발생 빈도
- 핵심 데이터 확보 가능성
- 기술 성능과 정확도
- 법률 및 규제 해석
- 경쟁 서비스의 성과

공식 원출처 하나가 사실을 직접 확정하는 경우에는 중복 출처보다 원출처의 명확성을 우선할 수 있다.

## 9. 조사 종료 조건

- 모든 핵심 전제에 확인 결과 또는 확인 불가 사유가 있음
- 차단 가능성이 있는 의존성을 직접 확인함
- 주요 외부 주장에 적절한 원출처가 있음
- 추가 검색이 종합 판정을 바꿀 가능성이 낮아짐
- 남은 불확실성과 해소 방법이 명시됨

시간, 비용 또는 접근 제한으로 중단할 경우 완료가 아니라 `제한된 조사`로 표시한다.

## 10. 최신성

자료의 허용 연령은 고정하지 않고 변화 속도에 따라 결정한다. API, 가격, 법률과 제품 상태는 평가 시점에 다시 확인한다. 오래된 자료를 사용할 경우 현재에도 유효하다는 근거 또는 한계를 기록한다.

## 11. 금지 사항

- 검색 결과 스니펫만 인용하기
- 2차 자료의 인용을 원문 확인 없이 재사용하기
- 뉴스가 인용한 수치를 원문 통계·논문·공시 확인 없이 확정하기
- 다른 국가의 통계를 현재 대상 국가의 값으로 대체하기
- 논문의 가능성을 상용 구현 가능성으로 동일시하기
- 데이터셋 이름만 확인하고 필드와 이용 조건을 생략하기
- 무료라는 이유만으로 상업적 이용·가공·AI 처리·재배포가 가능하다고 추정하기
- 출처가 충돌할 때 유리한 자료만 선택하기
- 접근할 수 없는 내부 자료를 확인된 것으로 표시하기
