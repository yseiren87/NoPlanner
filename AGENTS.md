## 2. Agent operating rules

<!-- yjcli:rules -->
### Working with this file

- Shared by every coding agent. `CLAUDE.md` only imports this file (`@AGENTS.md`).
- Blocks between `<!-- yjcli:… -->` markers are regenerated by `yjcli update`;
  edit everything outside them freely.
- Never edit rendered yj skills. Put project-specific skill rules in
  `.yjcli/skills/<skill>.md`; yjcli appends them to that skill on every render.

### Output & docs

- Present results concisely; summarize as a table when possible.
- Show only the summary. Do not dump raw execution output, full logs, or intermediate artifacts.
- No filler, no repeated explanations.
- Switch to detailed output only when the user explicitly asks (e.g. "자세히"): keep the table first, then reasoning and the key code excerpts.
- Do not create or modify docs (README, etc.) unless the user explicitly asks. When editing a doc, rewrite it in context so it stays in sync with the code.

## 3. Repository layout

<!-- yjcli:layout -->
| Path | Role |
|------|------|
| `AGENTS.md` | Agent / contributor guide (this file) — source of truth |
| `.gitignore` | Ignore rules (the `# >>> yjcli` block is managed) |
| `.yjcli/manifest.toml` | yjcli selection state — do not edit by hand |
| `.yjcli/skills/<skill>.md` | (optional) project-specific rules appended to that rendered skill |
| `CLAUDE.md` | Claude Code entry — imports `AGENTS.md` (`@AGENTS.md`); do not edit |
| `.claude/skills/` | Claude Code skills (rendered by yjcli) |
| `.claude/settings.json` | Claude Code settings |
| `backend-msa/` | gRPC microservices sharing one proto contract — skill `yj-backend-msa` |
| `backend-msa/proto/` | gRPC/protobuf contract |
| `frontend/` | Vite + React + TS web apps — skill `yj-frontend` |
| `Makefile`, `make.bat` | Root entry — `make <platform> [NAME=<service>]` runs services via tools/runner |
| `tools/runner/` | Platform runner — `run.sh` / `run.bat` / `run.ps1 <platform> [service]` (managed by yjcli) |
| `tools/secrets/<platform>/<service>/` | Per-service env values (`.env.local-dev`, `.env.<environment>`) — committed in plain text |
| `tools/builder/` | Build/deploy — shared hosts and `steps/` (managed), `<platform>/build-*.sh` / `deploy-*.sh` (repository-owned); `make <platform>-build-<env>` / `-deploy-<env>` |
| `<platform>/<service>/Dockerfile` | Docker build stub for deployable services — delete it to opt a service out |
